## Explicit feature-disabled work

Real recovery/reset/step-up and session revocation; secure uploads/scanning; compliance approval; dispatch overrides and emergency access (D-11); driver split overrides (D-08); actual commission/split/cash/provider configuration (D-01–D-07); plans/billing (D-09); integrations (D-10); signed report/audit exports, retention and SLAs (D-12). Production approval transitions and provider processing are never inferred from sample state.

## Integration and compatibility

Route definitions and old design fixtures are separated. Existing sample URLs remain valid. New preview records have generated IDs; they resolve in the in-memory provider while navigating and show not-found after reset/refresh. Unknown named IDs and invalid tabs return HTTP 404 before rendering. These are frontend previews, not authenticated deep links.

See fleet-figma-inventory.md for the 45-frame reconciliation and fleet-preview-qa.md for test classifications/evidence.

## Workflow acceptance checkpoints

- F01: sample draft values survive all five application steps; final review displays all supplied values; submission is pending, never automatically approved. Security flows show unavailable/expired/retry states without accepting real credentials.
- F02: invitation acceptance produces a verification-pending sample driver. Expired/revoked invitations cannot accept. Vehicle registration/edit/renewal enters review. Driver/vehicle removal respects active assignments.
- F03: assignment checks current driver/license, vehicle/documents, critical issue holds and active assignment overlap. Invalid selections return actionable errors without writing an assignment.
- F04: fee-first sample math reconciles; split requests validate 100% and future dates; request history is separate from the sample trip snapshot. Cash scenarios retain outstanding commission after partial remittance.
- F05: reported → triaged → in_progress → resolution_submitted → resolved, with reopening; an independent document hold survives issue resolution.
- F06: Owner is required for team governance, team invitations and finance changes. Last-owner removal/demotion fails; transfer promotes the recipient before demoting the old owner.
- F07: local ticket replies and state changes survive navigation; report jobs explicitly advance through sample states and track sample download counts; read state/preferences and local audit details reflect mutations.
- F08: four responsive widths, market-scoped records, visible currency/timezone, keyboard-operable forms/dialogs, unsaved-draft warnings and correct unknown-route handling.

These are frontend acceptance checkpoints. Production checks remain classified separately in the QA report.
